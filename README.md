# MEXC-HARSI-Scanner

اسکنر مستقل HARSI برای قراردادهای USDT-M Futures صرافی MEXC.

## مشخصات

- بازار: قراردادهای فعال USDT Futures در MEXC
- فیلتر قیمت: کمتر از 30 USDT بر اساس آخرین قیمت معامله
- تایم‌فریم: 15 دقیقه
- تاریخچه ذخیره‌شده: دقیقاً 3 روز، معادل 288 کندل بسته‌شده برای هر نماد
- ورودی محاسبات HARSI: RSI وایلدر با طول 200 روی Close، High و Low
- Open Smoothing: برابر 1
- شرط سیگنال: HA_Close > 5.5 (بزرگ‌ترِ strict، نه مساوی)
- برای گرم‌کردن RSI/HARSI حداکثر 2,000 کندل بسته‌شده دریافت می‌شود؛ فقط 288 کندل آخر در دیتابیس نگه‌داری می‌شود.
- OHLCV خام و خروجی HARSI در دو جدول مستقل Supabase ذخیره می‌شوند.
- داده‌های قدیمی‌تر از سه روز پاک می‌شوند.

## اجرای Worker

نیازمند Node.js 22 یا بالاتر است.

    bash
    npm install
    cp .env.example .env
    # مقادیر Supabase را در .env تنظیم کنید
    npm test
    npm run scan


## روند اسکن

1. زمان سرور MEXC خوانده می‌شود.
2. قراردادهای فعال USDT با قیمت کمتر از 30 USDT انتخاب می‌شوند.
3. تا 2,000 کندل بسته‌شده 15 دقیقه‌ای برای هر قرارداد دریافت می‌شود تا محاسبات RSI و HARSI گرم شوند.
4. فرمول کندل HARSI از تابع f_rsiHeikinAshi() در Pine Script v4 پیاده‌سازی می‌شود.
5. فقط 288 کندل بسته‌شده آخر و نتایج HARSI متناظر با آن‌ها در Supabase ذخیره می‌شوند.
6. داده‌های قدیمی‌تر از سه روز از هر دو جدول پاک می‌شوند.

## ساختار

- src/mexc-client.js: ارتباط با API فیوچرز MEXC
- src/harsi.js: پیاده‌سازی HARSI مطابق Pine Script
- src/scanner.js: اجرای دریافت، محاسبه و ذخیره
- src/supabase-store.js: ذخیره‌سازی و پاکسازی
- supabase/schema.sql: ساختار جداول
- docs/technical-spec.md: مشخصات فنی و محدودیت‌های تطبیق

## نکته درباره تنظیمات RSI

در Pine Script اصلی، مقدار i_lenRSI = 7 و منبع OHLC4 مربوط به RSI جداگانه روی نمودار است. این دو مقدار در ساخت کندل‌های HARSI دخالت ندارند. کندل HARSI از i_lenHARSI = 200 و RSIهای جداگانه Close/High/Low استفاده می‌کند.
